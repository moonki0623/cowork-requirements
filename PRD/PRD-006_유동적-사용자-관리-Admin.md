# PRD-006: 유동적 사용자 관리 (Admin)

> **제품**: Jira·Confluence·Mattermost 공통 (Admin)
> **작성자**: 김문기 매니저
> **작성일**: 2026-07-10
> **최종수정**: 2026-07-13
> **상태**: `Open`
> **관련 이슈**: -
> **RFQ 영역**: 부가기능 (J/C/M)

---

## 1. 한 줄 요약 (One-liner)

> 로그인 시점 활성화와 LRU 회수만으로 500 라이선스를 수요 기반(on-demand)으로 운영하고, 임시 사용자·라이선스 보호 대상을 Admin이 직접 관리할 수 있게 한다.

---

## 2. 배경 & 문제 (Why)

- **현재 상황 (As-Is)**:
  - 인사 배치(CB01N210/CB01N310 적재) + `dept_license`(관리자 페이지 수기 관리) 조합으로 라이선스 보유 부서 소속 계정만 활성화 flag ON
  - 배치 운영은 **2개 관리 콘솔로 분리** — Atlas 배치(J/C·Crowd 연동, 라이선스 관리 포함) / Mattermost 배치(인사 DB·MM DB 연동), 양쪽 모두 매일 12:10 실행
  - 활성화 대상이 부서 단위로 **정적으로 고정** — 실제 로그인 여부와 무관하게 라이선스 슬롯을 상시 점유
  - Jira/Confluence는 Crowd(cwd_user) 경유, Mattermost는 API 호출로 users 갱신
- **발생하는 문제/불편**:
  - 500 라이선스 한도 내에서 미사용 인원이 슬롯을 점유해 실사용자 수용 여력 부족
  - 등록조직 외 예외·임시 인원(외주/협력사 등)의 접근 권한 부여 절차 부재로 처리 지연
  - automation·봇 계정에 대한 보호 장치가 없어 일괄 비활성화 시 자동화 장애 리스크 존재
- **왜 지금 해야 하는가**: 협업 범위 확대로 라이선스 수요 증가. 증좌 없이 500 한도 내 실사용자 기준 운영 체계 전환 필요

---

## 3. 핵심 목표 — 딱 하나 (Focus)

- **라이선스 점유를 "부서 소속" 기준에서 "실제 로그인" 기준으로 전환**하여 500 슬롯을 유기적으로 운영한다.

---

## 4. 하지 않을 것 (Non-Goals)

- **정기 전체 라이선스 비활성화 배치 도입** — 슬롯 회수는 LRU 수요 기반으로만 수행 (매일/7일 주기 전체 비활성화 없음)
- 인사 연동(CB01N210/CB01N310 적재) 체계 자체의 변경
- 권한(Role) 모델 자체의 재설계
- `dept_license` 폐기 — **자격(eligibility) 판정용으로 유지** (슬롯 점유 관리와 분리, Crowd/MM 별도 관리)
- Crowd 대체 또는 SSO 신규 도입
- 라이선스 증좌 협상

---

## 5. 성공 기준 (Measurable Success)

| 지표 | 현재 | 목표 | 측정 방법 |
|------|------|------|-----------|
| 활성 라이선스 계정 수 | 통제 없음 | 상시 ≤ 500 (시스템별) | DB 집계 / 시스템 로그 |
| 로그인 시 활성화 추가 지연 | - | ≤ 2초 (벤더 협의) | 로그인 응답시간 측정 |
| 슬롯 소진 시 로그인 거부 | - | 0건 (LRU 회수로 즉시 슬롯 확보) | 감사 로그 |
| automation·봇 계정 오비활성화 | 보호 장치 없음 | 0건 | 감사 로그 |
| 임시 사용자 Admin 셀프 등록 | 불가 | 가능 | 기능 확인 |

※ 로그인 추가 지연 목표치(≤ 2초)는 수치 기준 부재 시 검수 불가하므로 개발 착수 전 벤더와 확정 필요

## 6. 사용자 & 시나리오

- 대상 사용자: 시스템 Admin, 전체 임직원(로그인 활성화는 사용자 무인지 동작), 임시 사용자(외주/협력사)
- 사용자 스토리:

```
As a Admin,
I want to 라이선스를 로그인·LRU 기반으로 자동 운영하고
         임시 사용자·보호 대상 계정을 시스템별로 직접 등록/관리하여,
So that 500 한도 내에서 실사용자 누구나 지연 없이 협업 도구를 쓰게 한다.
```

- 핵심 시나리오:
  1. **로그인 활성화**: 사용자가 로그인 시도 → 자격 확인(시스템별 dept_license 또는 임시 등록) → 활성화 + 기존 팀/권한 그룹 복원 → 로그인 완료
  2. **슬롯 소진 시 LRU 회수**: 500 슬롯이 가득 찬 상태에서 로그인 → LRU(최장 미접속자, 보호 대상 제외) 자동 비활성화로 슬롯 확보 후 활성화 — 정기 전체 비활성화 없음
  3. **임시 사용자 로그인**: 통합인증 자동 재시도를 FE에서 3회 카운트 → 3회 도달 시 즉시 임시 사용자 전용 ID/PW 로그인 UI로 전환 → 로컬 자격증명으로 로그인
  4. **임시 사용자 관리**: Admin이 각 배치 콘솔(Atlas: J/C, Mattermost: MM)에서 기간(시작~종료)을 지정해 개별 등록 → 기간 내 로그인 가능 → 만료 시 자동 비활성화(알림 없음)
  5. **보호 대상**: Admin이 automation/봇 계정을 등록 → LRU 회수 대상에서 영구 제외
  6. **세션 활동 재개**: 비활성화된 계정이 살아있는 세션으로 활동 → 자동 재활성화 + 그룹 복원 (강제 로그아웃·재로그인 요구 없음)

## 8. 제약 / 가정 / 의존성

- **제약**:
  - 폐쇄망 환경 — 외부 서비스 연동 불가
  - Mattermost 2-node HA — 스케줄·싱글턴 동작(만료 처리 등)은 **DB 기반 락 필수** (in-memory 상태 관리 시 노드 수 배수 중복 실행)
  - 각 시스템(J/C/M)별 사용자 관리 방식 상이 (J/C: Crowd 통합, MM: 로컬 + custom 인증 플러그인)
  - 라이선스: J/C는 Crowd 기준 통합 500, Mattermost는 별도 500 (계약 확정) — **풀·자격·임시 사용자 데이터와 관리 UI 모두 콘솔별(Atlas/Mattermost) 완전 분리**
- **가정**:
  - **자격(eligibility)과 점유(occupancy)의 분리** — 자격 = 해당 콘솔에 등록된 `dept_license` 부서 소속 또는 임시 사용자, 점유 = 로그인 기반 활성화 (시스템별 독립 판정)
  - **슬롯 회수는 LRU 수요 기반으로만 수행** — 정기 전체 비활성화 없음. 슬롯 여유 시 비활성 사용자도 활성 상태 유지 가능하며, 슬롯 압박 시에만 최장 미접속자부터 회수
  - LRU로 항상 슬롯 확보가 가능하므로 자격 있는 사용자의 로그인은 거부되지 않음
  - **기존 세션 유지, 강제 로그아웃 없음** — 비활성화 이후 세션 활동 재개 시 자동 재활성화(FR-013)로 사용자 무중단 보장
  - 활성화 처리 장애 시 **개방(fail-open) 원칙** — 활성화 로직 실패가 로그인·업무 자체를 차단하지 않도록 설계 (상세 방식은 벤더 협의)
  - 장기 미사용 계정 잠금 등 내부 보안규정 요건은 본 체계와 별개의 기존 통제로 충족되는 것으로 가정 (해당 요건이 본 체계로 이관될 경우 별도 협의)
- **의존성**:
  - Crowd (cwd_user, 그룹 체계), 기존 배치 시스템 2종(Atlas 배치·Mattermost 배치, 수정 범위 포함 — 디무브 계약 범위), `dept_license`
  - Mattermost custom 인증 플러그인 (기존 자산 확장), Jira ScriptRunner
  - 통합인증 연동 로그인 화면 (FR-014 전환 UI의 개조 대상)

## 9. 디자인 / UI

- [ ] 와이어프레임 / 목업:
- 주요 화면 흐름: **기존 2개 배치 콘솔에 각각 라이선스 관리 UI 구성 — 완전 분리 운영**
  - **Atlas 배치 콘솔 (Crowd·J/C)**: 현행 '라이선스 관리' 팝업 확장 → 4개 탭
    1. **조직 라이선스**: J/C 자격 `dept_license` 부서코드 추가/삭제 (현행 기능 승계)
    2. **임시 사용자**: J/C 임시 사용자 목록 + 추가/삭제/편집 (계정, 소속, 활성 기간, 등록자)
    3. **활성 현황**: J/C 활성 사용자 테이블 (유형 구분, 마지막 로그인 정렬)
    4. **보호 대상**: J/C automation·admin 화이트리스트 (유형·사유 필수 입력)
  - **Mattermost 배치 콘솔**: 동일 구조의 라이선스 관리 팝업 **신설** → 4개 탭 (MM 자격 부서 / MM 임시 사용자 / MM 활성 현황 / MM 봇 화이트리스트)
- 두 콘솔은 데이터·화면·정책 모두 독립 — 상호 참조나 공용 테이블 없음
- **로그인 화면 (FR-014)**: 통합인증 로그인 기본 표시(실패 시 자동 재시도) → FE에서 재시도 3회 카운트 → 3회 도달 시 즉시 임시 사용자 전용 ID/PW 로그인 폼으로 전환
