- 일정 수정 완료 후, 연결된 자원(booking_id)이 있으면 **"자원도 수정하시겠습니까?" 확인 다이얼로그**를 띄운다. (수정)

## 2. 기대 결과 (To-Be)

- 일정 수정 완료 + 연결 자원 有(DateID/BookingID Not Null) → "자원도 수정?" 확인 다이얼로그 노출. (수정)
- 예 → 자원 수정 팝업: 저장된 booking_id(BookingID) / date_id(DateID) 로 예약현황에서 기존 예약을 매칭·세팅. (수정)
- 자원 수정 팝업 흐름은 등록과 동일: [자원 수정하기] → 빨간 줄 결과 → (만실로 시간 변경 시) "일정 시간도 수정?" → 일정 수정. (수정)
- 아니오(또는 연결 자원 없음)이면 일정만 수정(예약 변경 없음). (수정)

## 6. 구현 메모

- 트리거: 일정 수정 완료 시 연결 자원(booking_id) 존재 여부 확인. (수정)
- 매칭: outlook_calendar의 booking_id/date_id로 예약현황 조회에서 필터링
- 자원 수정은 **별도 팝업**이며, 버튼/빨간 줄 결과/만실 연계 로직은 ISSUE-017(자원 등록)과 동일하게 재사용. (수정)
- 관심회의실 트리 컴포넌트는 회의실 함께보기 팝업(ISSUE-015)과 UI 공유.
- 시간표 시간대 클릭 → 예약 폼으로 시간/장소 매핑 + 포커스.
- 🔵 **[승인분류] 승인 분류 판별**: 자원 상세조회 API(resourceId)로 바로승인/담당승인을 조회하여, 예약 수정 API 성공 시 토스트를 분기한다. (신규, ISSUE-017/023 참조)

- 자원 목록 API -> [ISSUE-015 참조](issue/ISSUE-015_캘린더-회의실-함께보기-팝업-추가)
- 예약 현황 API -> [ISSUE-016 참조](issue/ISSUE-016_캘린더-회의실-함께보기-일정표출)
- 예약 등록 API -> [ISSUE-017 참조](issue/ISSUE-017_캘린더-일정-등록-시-자원-예약-추가)
- 예약 수정 API -> [ISSUE-017 참조](issue/ISSUE-017_캘린더-일정-등록-시-자원-예약-추가)
