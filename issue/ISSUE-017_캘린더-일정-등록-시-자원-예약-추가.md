## 1. 현상 / 요청 내용
- 일정 등록과 자원 예약을 **별도 팝업으로 분리**한다. **(수정)**
- [새 일정] 진입 시 **자원예약 / 일정등록 분기 선택 화면**을 먼저 노출하고, 선택한 흐름의 팝업으로 진입한다. **(신규)**
- **일정 등록 팝업**: 일정 제목 / 일정 내용 / 시간 / 참석자 / 장소 + [일정 등록하기] 버튼. **(수정)**
 - **자원 등록(예약) 팝업**: 관심회의실 → 회의실 시간표 → 자원 예약 폼 + [자원 예약하기] 버튼. **(수정)**
 
- 관심회의실 선택은 자원목록 API 연동을 통해 트리 - 체크박스 표시 구조로 설계한다.
  - 관심회의실 선택은 user_favorite_room 테이블에 저장한다.
  - 관심회의실을 선택하는대로 회의실 시간표에 표출한다.
  - 관심회의실 선택은 기존의 선택한 유저는 트리구조 ROOT 항목만 표출한다.
 
- 회의실 시간표는 관심회의실에서 선택한 회의실들을 표출한다.
  - 예약현황 API 호출 후 resourceID와 매핑되는 것으로 시간표를 표출한다.
  - 1일 뷰만 제공하며, 일자는 일정 등록의 일자와 동일하게 설정한다.
  - 과거일자의 경우 오늘로 Default 설정을 진행한다.
  - 과거일자는 볼 수 없다.
  - 모바일 기준 3개의 회의실이 넘어가면 좌우스크롤로 표출한다.
  - 현재 시간보다 이전 시간의 영역은 터치가 불가능하며, 이후 시간을 선택할 시 해당 시간과 해당 회의실로 하단의 자원 예약 INPUT의 자동 매핑 및 포커스 이동을 진행한다.
  - 🔵 승인 여부와 관계없이 캘린더 일정에 표출해야한다. (승인 거절 시, 예약현황 API에서 전달안함. **승인대기상태여도 표출 필수**)
 
- 자원 예약 폼
  - 폼 UI에는 **용도 / 예약시작(일자·시·분) / 예약종료(일자·시·분)/** 만 노출한다. (수정)
  - 예약자·소속부서·자원명·자원분류·최소대여기간 등 **고정 정보 필드는 수정이 불가하게 세팅**한다(값은 예약 등록 API 전송 시 내부 고정 매핑). (수정)
  - ·담당자·반납절차·예약절차·사업장 은 화면에서 표출을 제외한다.
  - 값 매핑 (수정가능)
    - 용도 : 일정 제목과 매핑
    - 예약시작일자 / 예약시작시간 / 예약시작 분 / 예약종료일자 / 예약종료시간 / 예약종료 분
      - 일정 시간과 자동 매핑, 5분단위로 내림 처리
      - 최소 시간 30분 안내멘트 필요
 
- 자원 예약하기 버튼
  - 자원 예약 폼의 내용을 가지고 예약 등록 API 발송
  - **응답 결과는 버튼 하단 '빨간 줄'로 실시간 표시**(성공/실패)한다. (수정)
  - **만실 등 실패 시**: 사용자는 회의실 시간표에서 **자원 시간을 수정해 재시도**하거나, 자원 예약 없이 **[일정만 단독 등록]** 을 선택할 수 있다. (수정)
  - **자원 시간이 변경되어 일정 시간과 달라지면** "일정 시간도 수정하시겠습니까?" 확인 후 **일정 수정**으로 연계한다. (신규) (현재는 구현 목록 제외 -> 추가될 수 있음 ✔️)
- 
- 팝업 간 연계 흐름 (양방향) (신규)
  - [신규] 일정 등록 완료 → "자원도 예약하시겠어요?" → 예 → 자원 등록 → **[optional]** (만실로 시간 변경 시) "일정 시간도 수정하시겠어요?" → 예 → 일정 수정 (신규)
  - [신규] 자원 등록 완료 → "일정도 예약하시겠어요?" → 예 → 일정 등록 (신규)
 
 - 🔵 **[승인분류] 성공 시 토스트 분기** (수정): 예약 등록 API 성공(Reason "OK|DateID") 시 회의실 승인 분류에 따라 토스트 팝업을 분기한다.
    - 🔵 **바로승인** → "**바로 승인되었습니다.**"
    - 🔵 **담당승인** → "**담당자 승인이 필요한 회의실입니다. 승인 여부는 마이스퀘어를 통해 확인 부탁드립니다.**"
 - 🔵 **[승인분류] 중복 신청 방지** (신규)
    - 🔵 **담당승인 회의실**의 경우, 예약 등록 API는 동일 요청을 여러 번 보내도 매번 OK를 반환하므로, **한 번 OK되면 종료(재전송 금지·멱등 처리)** 한다.
    - 🔵 (**optional**) 해당 자원의 해당 시간과 **겹치는 신청(승인 대기 포함)** 이 이미 있으면 **프론트에서 신청을 차단**한다. (기존 마이스퀘어 자원예약도 프론트에서 승인 대기 자원 신청을 막고 있음)

## 6. 구현 메모

- 일정 등록 / 자원 등록은 **별도 팝업**이며, 진입 시 분기 선택 화면을 먼저 표시한다(단일 인라인 팝업 아님). (수정)
- 관심회의실 트리 컴포넌트는 회의실 함께보기 팝업(ISSUE-015)과 UI 공유.
- 시간표 시간대 클릭 → 예약 폼으로 시간/장소 매핑 + 포커스.
- 자원 예약 폼은 고정정보 필드를 표시하지 않으나, 예약 등록 API BODY에는 아래 고정 값들이 그대로 매핑되어 전송된다. (신규)

- 자원 목록 API -> [ISSUE-015 참조](issue/ISSUE-015_캘린더-회의실-함께보기-팝업-추가)
- 예약 현황 API -> [ISSUE-016 참조](issue/ISSUE-016_캘린더-회의실-함께보기-일정표출)
- 🔵 **자원 상세조회 API (신규)**
- 예약 등록 API
  - 요청 BODY JSON 항목
    - ResourceID : 자원 ID
    - BookingID : 0으로 고정으로 파악됨 ✔️
    - Description : 용도
    - SubscriberID, DelegatorID : 예약자 사번으로 고정 ✔️
    - isAllDay : N으로 고정 ✔️
    - StartDateTime : 시작시간
    - EndDateTime : 종료시간
    - RepeatYN : 반복여부 N으로 고정 ✔️
  - 응답 JSON (값의 의미는 IT지원팀 확인 필요 ✔️)
    - Result : 응답결과 -> 실패하더라도 true로 발송됨
    - Reason
      - 성공 -> "OK|DateID"
      - 실패 -> "CheckBooking|시간"
  - 참고사항
    - 성공여부를 Reason의 내용을 기준으로 판별해야함.
    - 실패("CheckBooking|시간") 시 빨간 줄로 표시하고, 시간 수정 재시도 또는 일정만 단독 등록으로 분기한다. (신규)
    - 고정 값으로 매핑한 컬럼들은 메터모스트에서 기능 사용을 하지 않을 것임(화면 미표시). (수정)
- 예약 수정 API
  - 예약 등록 API와 유사
  - BookingID 만 현재 예약 ID로 매핑 필요
